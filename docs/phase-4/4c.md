# Phase 4C — migration and export

The expanded adapters feed the existing owner-authorized canonical import plan. Review, resumable commit cursor, idempotency, revision conflict checks, original files and reconciliation reports remain the authority. HTML never enters the WebView as executable source.

## Implemented

- HTML/HTM documents and ZIP members: headings H1–H4, paragraphs, lists, quotes, code, supported marks, links, managed media, and bounded tables including row/column spans. Unsupported active content and malformed tables receive partial/readable fallback outcomes and retain original bytes. Links resolve across ZIP pages/assets. Scripts, frames, styles and unsafe URL schemes are not rendered. HTML database row bodies can be matched to supplied CSV rows.
- TXT/DOCX documents: the existing bounded document extractor creates canonical readable blocks, with explicit partial/unsupported evidence when extraction cannot preserve the supplied format. PDF files remain managed attachments for the existing document extraction pipeline.
- Native folder import explicitly copies a selected root into a bounded archive; symlinks and devices are skipped, paths remain confined by `os.Root`, and archive inventory retains all copied sources. Limits: 10,000 entries, 64 nesting levels, 64 MiB/member, 1 GiB total. A folder copy is distinct from reference-only indexing.
- Portable manifest import validates canonical blocks, remaps page/file/block IDs, preserves parent ownership, tables and merge evidence, and restores same-page layouts/reusable sources. Cyclic, malformed, activation-dependent or unresolved constructs retain original canonical JSON as readable evidence instead of becoming live actions. Generated HTML renditions are retained once without creating duplicate canonical pages.
- Canonical portable database manifests reconstruct supplied property schemas/options, typed values, stable references, relations, supported formula/rollup definitions and the six supported views. The preview freezes a bounded graph (256 properties per collection, 5,000 entities total); all cross-collection definitions commit together through normal guarded handlers after page import. Identity remapping preserves original formula expressions, imported caches and opaque text, while translated expressions and typed references use new local IDs. Linked-view owning pages are exported explicitly and restored. Unsafe/incomplete graphs fall back to readable CSV plus retained manifest evidence with a partial outcome; unsupported views remain evidence. Keeping an existing database never activates an incoming graph.
- HTML export creates an offline ZIP with CSP-protected script-free HTML, page and attachment links, readable advanced-block labels, CSVs, original Markdown and the exact canonical manifest. Unknown block data stays readable and lossless in canonical JSON. Phase 4 metadata (including automation definitions) is evidence on re-import, never silently activated.
- PDF export uses the macOS print converter for a readable text rendition with Unicode. The native API returns the limitation that rich layout, attachment bytes and exact schemas require HTML/portable export. The converter has a 60-second deadline, 32 MiB input and 256 MiB output bounds, exclusive destination creation, and incomplete-output cleanup. Other platforms return an explicit unsupported result with HTML/Print to PDF guidance.

## Optional authenticated Notion capture

`imports.notion.start/list/status/step/finish` operate on explicit page-root UUIDs. The token is accepted per `step`, sent only to `api.notion.com`, never placed in SQLite, cursor JSON, files or browser storage. A trusted injected HTTP client exists for qualification tests; renderer dispatch cannot choose the API origin or redirect policy. Integration secrets are not managed as a persisted connection.

The adapter pins Notion version `2025-09-03`, requests pages and paginated block descendants with at most 100 blocks/response, and retains every supplied response before import. Captures have a compare-and-swap revision and durable pending cursors. Maximums: 20 roots, 64 levels, 10,000 items/responses, 128 MiB/capture, 4 MiB/API response, 16 MiB/attachment, 45 seconds/step. Transient responses receive at most three attempts; `Retry-After` longer than two seconds pauses at the persisted cursor for later user resume. Permission errors remain visibly blocked and retain the response. Partial completion requires an explicit action and reconciles unread sources as failed, preserving unavailable child-page references.

Hosted attachments use a narrow HTTPS Notion/AWS storage allowlist. Redirects are denied, and bearer credentials are never sent to storage. Successful downloads become hash-checked managed assets. External hosts, failed downloads and over-budget resources have partial outcomes and readable evidence; no offline-availability claim is made for missing bytes.

Supported text, marks, code, media and page hierarchy become canonical content. Supplied non-page parents now reconstruct nested content, toggle/list ownership, column groups and safe same-page reusable sources; HTML/Markdown structure and stable source block identity are covered by the [nested import completion notes](../completion/import-structure.md). Unsupported semantics remain explicitly partial with exact source evidence. Supplied property values, unsupported schemas/relations/views and computed values remain labeled source snapshots; they are not silently reconstructed as live formulas or freshly calculated results. Page/block capture does not pretend to obtain database schemas or views that these endpoints do not supply. Source mappings require ordinary conflict review on re-import.

The UI supports root selection, a memory-only password field, saved-cursor resume, pausing between requests, and complete/partial inventory review. Live authenticated account qualification remains unverified; offline mocked transport tests establish the behavior above, not vendor-account compatibility certification.

Primary API references checked 2026-09-30: [block children and pagination](https://developers.notion.com/reference/get-block-children), [request limits](https://developers.notion.com/reference/request-limits), [file URLs](https://developers.notion.com/reference/file-object). Firecrawl DNS was unavailable in this environment, so official sources were inspected through the available web tool.

## Validation

`import_expanded_test.go` covers inert HTML, H4/marks/internal links, offline HTML/CSP, folder symlinks/document extraction, owner permissions, reviewed web capture and native macOS PDF output. `import_notion_test.go` uses a fixture HTTP transport to verify authentication ownership, rate limits, pagination, stale cursors, credential non-persistence, offline attachment retention, denied roots, explicit partial completion and commit-before-review rejection. `TestPortableCanonicalDatabaseRoundTripRelationsFormulasAndLinkedViews` verifies live rollups after remapping, exact formula/cache evidence, literal UUID text, typed options and linked view placement. Existing portable importer tests also pass.

Run with the pinned Go toolchain and `-tags 'fts5 sqlite_omit_load_extension'`.
