# Phase 4B — Advanced databases and formulas

Implementation: `internal/workspace/advanced_database.go`, `formula.go`, `formula_translation.go`; `frontend/src/database/AdvancedDatabase.tsx` and the existing database view/service.

## Canonical behavior

- Gallery (including local image covers), timeline, table, list, board and calendar reference one canonical collection. Linked views use an independent owning page, retaining collection/record/property IDs. Queries reject cursors after any committed workspace dependency change or clock minute change; this is intentionally conservative.
- Relations use stable record/property IDs, indexed `relation_edges`, one/many cardinality, and optional explicitly reciprocal definitions. Reciprocal values change atomically and require guards/permissions for both properties, collections, record pages and affected records. Creating reciprocal definitions requires both definitions in the same batch. Missing reciprocal guards never cause an unguarded write.
- Rollups support count, sum, average, min, max and show-original. Related records outside the granted scope return an unavailable diagnostic without exposing their content. Numeric rollups ignore empty values; count counts related records; an empty numeric set yields empty.
- Formula and rollup definitions retain the existing canonical fallback envelope. Its `raw` contains separate `originalExpression`, `translatedExpression`, and optional `importedCachedValue`. Rollups use `relationPropertyId`, `targetPropertyId` and `aggregation`. Per-record imported formula evidence in property values is also retained. The evaluator never substitutes a captured result for a computed result. Errors return a diagnostic, a null live value, and a separately labeled captured value when supplied.
- Derived results are recalculated from the current read transaction. There is no stale derived cache. Property dependency cycles are rejected before definitions commit; runtime record/property recursion is bounded as well. Formula filters/sorts use live values, and unavailable calculations compare as empty.
- Created/edited time and unique ID project the canonical record-page creation/edit instants and stable record UUID. Historical imported metadata remains in canonical property values/export evidence; native controls do not edit these projections. Identity names and place labels are editable while retaining unrelated place evidence. Relation, identity and place values use their existing schemas.
- Database locks reject schema, record-property, record-title and record-body writes through the commit validator. Lock/unlock is an isolated guarded command. Saved view layout changes remain available.
- Sub-item parents and dependencies are collection-local, guarded, and independently cycle checked. Record templates copy editable property values into new canonical record/page identities. Page/body templates use the Phase 4A template library.

## Supported formula compatibility matrix (interpreter v1)

| Feature | Supported behavior |
| --- | --- |
| Literals | Decimal numbers, quoted strings, `true`, `false`, `null` |
| Arithmetic | `+`, `-`, `*`, `/`, unary `+`/`-`, parentheses; exact rational intermediates; final numbers rounded to 12 decimal places |
| Comparisons | `==`, `!=`, `<`, `<=`, `>`, `>=`; numeric and text ordering |
| Boolean | `&&`, `||`, `!`; short circuit; strict boolean operands |
| Conditional | `ifElse(condition, trueValue, falseValue)`; lazy branch selection |
| Properties | `prop("stable-property-id")`; static local collection property references |
| Math | `abs`, `round` (nearest integer, ties away from zero), `min`, `max` |
| Text | `length` (Unicode code points), `lower`, `upper`, `contains`, `concat` |
| Empty | `empty` for null, empty text, empty lists |
| Clock | `now()`, `today()` using an explicit instant/timezone |
| Imported source subset | `if(...)` translated to `ifElse(...)`; `prop("source name")` resolved through explicit stable-ID mapping; supported operators/functions above |
| Unsupported | Arbitrary code/member access, loops, callbacks, regex, dynamic property lookup, list map/filter, date arithmetic, network/filesystem/process functions, proprietary functions outside this matrix |

`TranslateImportedFormula` returns no executable translation for unsupported functions or unmapped property names. Adapters must retain original source and imported caches separately regardless of translation outcome. This matrix does **not** claim complete Notion formula parity.

Limits: 8 KiB expression, AST evaluation depth 48, 1,024 evaluation steps, 4,096-bit rational operands, 64 variadic arguments, 64 KiB generated text, 1,000 related records per rollup and 10,000 property evaluations per query. There is no dynamic code execution.

## Clock rules

Normal record queries share a UTC clock snapshot rounded down to the minute. The database UI refreshes once per minute while mounted. `databaseDerived` can accept an explicit RFC3339 instant and IANA timezone for deterministic previews/reference fixtures. `today()` follows that timezone's calendar date; timed formula results are derived and never written back as captured source values. Calendar/timeline source dates retain the timezone in the date envelope.
