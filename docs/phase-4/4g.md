# 4G — Provider and MCP adapters

The Providers surface exposes explicit page/capability selection, a shared-context manifest, pairing, pending proposals with exact commands/revisions, approve/deny, local disconnect and a reviewed handoff preview. Local AI remains the default. A connection never enables API billing.

## Paired MCP

The desktop creates a bounded loopback-only HTTP endpoint after the user approves a page manifest and tools. A per-connection random bearer credential stays in memory and is shown once for explicit client configuration. Browser origins are denied, credentials are never placed in URLs, redirects are refused by the relay, and requests/responses are bounded. The included `cmd/trove-mcp` stdio relay forwards JSON-RPC to that endpoint; it never opens SQLite. Build with `python3 scripts/build-desktop.py --phase4 --output build/phase4-preview/Trove.app` to include the signed relay.

The protocol subset supports initialize, ping, tools/list, tools/call and initialized notifications with JSON responses (protocol 2025-03-26). It does not provide remote OAuth, server push or a hosted/tunnel endpoint. Remote transport remains disabled. Tools are scoped readPage, queryRecords, search.query, resolveCitation, allocateIds and proposeChanges. The bridge restricts proposals to updates/inserts within approved context; deletion, new pages and arbitrary filesystem tools are unavailable. The person approves exact commands in Trove, and canonical Batch enforces grants, revisions, locks, registry rules and idempotency.

Proposals, outcomes and audit metadata are persisted without pairing or vendor credentials. Changed retries fail; successful repeated approvals return the same receipt. Disconnect cancels read contexts, revokes the kernel grant and interrupts pending proposals. Restart disconnects connections and interrupts unapproved proposals; it does not secretly reauthorize a client. A grant fence linearizes permission revocation with canonical transaction commit. Existing vendor sign-in is never silently revoked.

## Separate managed adapters

`internal/providers` supplies separate Claude Code and Codex adapters behind the same capability, connect/status, start/resume/cancel/disconnect interface. They validate identity/account/auth/billing/runtime/adapter compatibility, decode bounded vendor streams, handle approval events, reject premature EOF as success, and build argument-array commands without a shell. Codex requires a successful `turn/completed` status; Claude requires a successful result. Resume requires the same account, provider, version, scope and policy. Handoffs are explicit task/result/pending-work plus current source manifest and require fresh authorization; no hidden reasoning or native session crosses providers.

Managed vendor modes are **not enabled in the desktop**. The adapter protocol and command construction are tested with fixtures; there is no qualified process launcher, Trove-owned SIWC + Keychain/JWKS/refresh integration, or live vendor entitlement/distribution/containment evidence in this build. Passing booleans in a Go test profile is not qualification. The UI displays this limitation and refuses connection rather than claiming sign-in success. Authentication owner remains Claude's unchanged official runtime for Claude Code and Trove's official SIWC integration for Codex. API-key mode must be separately selected and qualified; there is no fallback.

Official sources checked 2026-09-30:

- [Codex app-server via SIWC](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server): public Responses route, child-only access token, initialize/turn lifecycle and explicit successful completion.
- [SIWC overview](https://developers.openai.com/siwc/token-sharing-open-source): supported integration and current eligibility/distribution conditions must be qualified for Trove's distribution.
- [Claude Code integration conditions](https://code.claude.com/docs/en/legal-and-compliance) and [CLI reference](https://code.claude.com/docs/en/cli-reference): unchanged runtime and vendor-owned authentication, strict MCP configuration, disabled built-in tools. Trove does not collect copied subscription credentials.

The Phase 4G shipping gate remains open for real vendor sign-in/stream/resume and OS containment, remote transport qualification and independent client interoperability. Local paired-MCP service tests cover denied tools, wrong credentials/origin, scoped reads, exact approval, stale revisions, changed retry payloads and revoked connections.
