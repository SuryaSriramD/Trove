# 4F — Expanded local assistance

The Local AI operation selector includes database/schema drafts, Mermaid, code explanation/refactoring/commenting, organization suggestions, and bounded workspace-agent plans. These use the existing installed local instruction model, scoped retrieval, source revision manifests, conversation history, cancellation and streamed draft UI.

Generated content stays a draft. Review offers a database from JSON, insertion/replacement of Mermaid, replacement of a unique selected code range or a fully supplied code block, and a bounded workspace command draft. The user can edit the draft and inspect exact before/after content before approval. Database drafts allocate canonical identities, validate property configs and views, and create one collection with one view in a canonical atomic batch. Selected-code replacement preserves surrounding code; whole-block replacement is denied if retained model context omitted any original source. Code remains text; nothing invokes it. Code and JSON output bypass prose citation substitution so indexing expressions such as `values[2]` survive unchanged.

Database JSON shape:

```json
{"title":"Reading","properties":[{"name":"Pages","type":"number","config":{"format":"decimal"}}],"view":"gallery"}
```

The service creates the Name/title property. Names must be unique; at most 32 properties; supported generated view choices are table, list and gallery. Property configs use the registry. A schema change to an existing collection or a more advanced view can be proposed as `workspace_patch`, with `commands` and `expectedRevisions` arrays. That draft is restricted to page update/move, block insert/update, property addition, view save and record value set/clear, bounded to 32 changes. Structure validation precedes preview and the complete canonical validation, permission, lock and revision gates run on approval. Generated identifiers and references must be valid; unsupported output is diagnosed and stays a draft.

The service checks Mermaid declarations and rejects executable markup, init directives and click links. Before enabling AI approval, the desktop parses the exact source with the installed Mermaid parser, including Mermaid blocks in broader workspace proposals. Malformed diagrams stay editable drafts; nothing is executed. The service validates the safe source envelope, while full grammar validation belongs to the desktop. Rendering uses the editor's inert SVG path and preserves source on renderer errors.

The page AI panel offers related/duplicate suggestions. These are labeled as deterministic vocabulary/exact matching, never mislabeled as model inference; optional semantic candidates use the installed embedding/search service and surface unavailable-model diagnostics. Organization/tag recommendations are prose until the user reviews a concrete action. Suggestions do not alter pages or automatically merge duplicates.

Approved batches preserve the exact proposal receipt and source guards, reject stale evidence, and atomically mark the proposal applied with its effects. Committed event/history origin is `ai`, allowing automation eligibility to remain explicit. Tests cover database creation with retry, invalid structured configs, literal code preservation, stale review denial, and unsafe Mermaid rejection. Live instruction-model quality across every new mode remains a separate qualification task; this is not evidence of benchmarked generation quality.
