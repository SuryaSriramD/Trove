# Phase 2B — Search and document extraction

Implemented in `internal/workspace/search.go`, `search_semantic.go`, `extraction.go`, `internal/workers/search.go`, and `frontend/src/search/SearchPanel.tsx`.

## Retrieval and navigation

- FTS5 indexes live page titles, readable block projections (including code, tables and retained unsupported readable text), canonical record/task property projections, extracted document sections and transcript text.
- Every structural chunk stores the source page revision, content hash and canonical location. Transcript chunks carry meeting/segment IDs and start/end milliseconds. File hits add file ID and PDF page number while preserving the attachment's page/block location.
- Canonical mutations add durable page invalidations atomically after revision updates. Search drains the queue in bounded transactions. Queries join live page revisions and exclude trash, preventing stale/deleted hits even before an invalidation drains. Rebuild reconstructs only derived index state; original document sections survive.
- Query scope intersects the authenticated scope. A renderer cannot widen a page/project grant by requesting workspace search. User text is quoted into literal FTS terms, never executed as raw MATCH syntax.
- `resolveCitation` validates page/block/transcript ownership, revisions, exact timestamp bounds and memory status. Excerpts are readable content, not raw block JSON. The integrated shell opens and highlights the correct block, or seeks the meeting audio.

## Extraction

`EXTRACT_DOCUMENT` jobs use payload `{kind:"file",fileId,extractorVersion:"trove-document-v1"}`. The job reads a hash-verified managed asset, performs decoding outside the workspace write lock, then commits sections under its lease and file revision. Repeated successful units are reused. Failure records a visible warning while retaining the original bytes.

Text, Markdown and CSV are decoded as bounded UTF-8; HTML excludes scripts/styles; DOCX reads its XML paragraph/table text without running macros or opening external resources. PDF uses the bundled, hash-verified PDFKit helper supplied by the desktop build. Development environments can fall back to `pdftotext`. Input is limited to 128 MiB, text output to 16 MiB, and PDF runtime to two minutes. The helper accepts PDF bytes on stdin and outputs page-separated UTF-8. No shell interpolation or external file path is passed to it.

PDF and DOCX extractions explicitly report partial fidelity. PDF scans/image-only regions require OCR (not supplied here); formatting, image contents, annotations and arbitrary embedded objects remain in the original document. Unsupported, malformed, encrypted and textless PDFs fail with a recoverable message, never a successful empty index.

## Optional semantic retrieval

`GENERATE_EMBEDDINGS` jobs store vectors against model ID, chunk content hash and source revision. Native work is routed through the existing scheduler with background priority; an interactive query gets chat priority. A document chunk is split into bounded text windows and its vectors are normalized/averaged so long content does not overflow the model context. Revision changes delete obsolete vectors. Semantic cosine ranking and hybrid reciprocal-rank fusion both recheck permissions and live revisions.

Search remains usable with no pack or a unavailable worker; hybrid/semantic requests visibly fall back to keyword results. The UI lists installed embedding packs, queues a semantic build, shows fallback warnings, offers keyword rebuild, and exposes extraction progress/retry through the existing Jobs UI. Current implementation uses a bounded native worker with scalar cosine scoring in Go; it does not yet use approximate-nearest-neighbor acceleration. An explicit “Keep semantic index updated” setting queues current source revisions after edits and file extraction, in batches of 32 pages. Index-generation and chunk hashes prevent reusing a completed job after rebuild or extraction at the same page revision. Failed inputs are attempted once automatically and remain available for manual retry in Jobs. Automatic indexing defaults off.

## Service surface

- Existing schema-valid `search` and `resolveCitation` remain available for AI services.
- `search.query` adds optional `kinds`, `pageId`, `modelPackId` and `semantic` mode, returning titled hits with attachment navigation metadata.
- `search.status`, `search.rebuild`, and `documents.status` expose derived status. Rebuild requires workspace owner context.
- `Kernel.RebuildSearch(ctx)` is available for staged native restore. Initializers and mutation projections self-register.
- `workers.ConfigureSearch(k, supervisor)` supplies the optional native embedding provider.
