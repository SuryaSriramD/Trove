# Phase 2C: local AI and approved memory

The desktop exposes Local AI in workspace navigation and on a selected page. Installed, hash-verified chat packs execute through the native priority scheduler. The Qwen2.5 1.5B instruction pack (105) is preferred when installed. Keyword search, page editing, and memory review do not require model packs.

## Implemented workflows

- Current-page, explicit-project, and workspace questions use current permission-filtered structural search excerpts. Workspace questions fall back to a union of literal keyword results when a natural-language question is too restrictive. Ordinary retrieval excludes every memory backing page; approved memory is added only through the separate live-validated path.
- Answers stream over `ai:progress`; final results, prompt, source context, citation identities, errors, and cancellation state persist in `ai_runs`. The frontend reconnects through persisted run queries. The preceding question is used for follow-up context only while its evidence remains live and its memory setting is compatible. Old assistant text is never recycled as authoritative evidence.
- Rewrite, summarize, explain, shorten, expand, outline, and page generation produce reviewable drafts. A selected text rewrite verifies the exact text still exists and uniquely matches its block. Generated Markdown headings and lists become canonical blocks.
- Page/block replacement, block append, page creation, and task creation require an explicit preview and approval. Before/after text is shown. Prepared commands and revision guards are frozen in `ai_proposals`, validated against the public batch contract, and checked again during atomic canonical commit. Task bootstrap, when needed, is part of the reviewed batch. Repeating approval cannot duplicate content.
- Conversations belong to their authenticated actor and are filtered against the current source permission scope. Cancellation stops native generation and saves partial text. Workspace switching/shutdown cancel and join active runs before closing their database. An interrupted run becomes cancelled on reopening.
- Preferences, project context, and evidence-linked decisions support propose, approve, edit, disable, supersede, forget, and restore. Editing clears approval and returns a proposed state. Context stores a canonical page reference instead of copying live record values. Decisions require evidence. A database-record page cannot be converted into a competing memory backing record.
- Project and page scope matching respects explicit membership/exclusions and explicit workspace/ancestor preference inheritance. Memory retrieval verifies every source revision, block identity, and transcript range. Source edits mark active dependent memory stale in the canonical mutation pipeline. A forgotten, disabled, superseded, stale, or deleted record is immediately excluded from subsequent retrieval.
- Evidence changes or forgotten memory during generation discard the final answer. Stored citations are revalidated when a conversation is read and before navigation. Reviewed actions recheck both evidence and canonical revision guards.

## Citation behavior

Citation numbers must resolve to source locations that were actually provided to the model and remain current. Unknown numbers are replaced with an unavailable-source marker. If the model omits citations, the service may append a source only when the **entire answer** is an exact substring of a current supplied source (at least 16 characters, ignoring case and terminal sentence punctuation). It does not guess a citation for a paraphrase. Other uncited results explicitly show that the context sources do not establish support for every generated claim.

Location validation proves identity, revision, access, and navigation target. It cannot prove semantic entailment of every model-written claim; users review generated prose and every mutation. The representative real-model fixture produces `The launch code is AMBER-27. [1]`, backed by an exact source sentence.

## Product boundaries

Context is bounded for the current 8K native model configuration. Current canonical content gets priority over at most two short memories. Excerpts or page sections omitted to fit the budget are disclosed in the answer. This is not a guarantee of exhaustive long-document synthesis. Prompts support 2000 UTF-8 bytes and exact text selections support 1200 bytes; oversized requests fail explicitly.

Whole-page replacement is offered only for plain, unnested text blocks. Structured/embedded pages can use appends or individual safe text patches. Replacement may remove formatting in the replaced text, disclosed in the review UI. Historical conversation text and forgotten policy records remain inspectable locally for recovery; they are not eligible evidence for a new answer until an explicit valid approval. This package does not implement the P1 autonomous workspace agent.

## Validation

`go test -tags 'fts5 sqlite_omit_load_extension' ./internal/workspace -run 'TestAI|TestMemory'` covers:

- approval, forgetting and explicit restoration, edit reapproval, source-change invalidation, and preventing an older superseded policy from reviving alongside a newer active replacement;
- controlled with-memory/without-memory fixtures and current-data authority instructions;
- forgotten evidence during generation discarding output;
- source-number rejection, exact-source attribution, and uncited-paraphrase disclosure;
- actor/scope isolation, cancelled runs, stale conversation context;
- reviewed append idempotency, selected-text patching, structured page generation, clean-workspace task creation, and plain-page replacement;
- stale evidence rejecting a previously reviewed action.

`TROVE_NATIVE_INTEGRATION=1 TROVE_MODEL_ROOT=/private/tmp/trove-phase1-models go test -tags 'fts5 sqlite_omit_load_extension' . -run TestRealLocalAIWorkflow -count=1 -v` passes against the real verified 1.5B instruction pack and rebuilt native helper. It verifies adapter → retrieval → native generation → durable answer → grounded citation. Native qualification requires the host permissions used by the native worker tests. The frontend passes TypeScript checking.

The isolated Playwright test `Phase 2 AI review shows exact before and after and applies only on approval` passes with a ready-model bridge fixture. It verifies readable original/resulting text, zero canonical writes during preview, exactly one apply after explicit approval, and navigation to the updated canonical page. This is a browser interaction test, separate from the real native-model qualification above.
