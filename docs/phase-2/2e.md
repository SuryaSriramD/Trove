# Phase 2E — recovery, native backup and staged restore

Implemented in the workspace kernel and desktop Recovery settings.

## Page history and trash

- Snapshots preserve page bodies, metadata, provenance, explicit attachment ownership, canonical record identity, page-owned property values and their historical definitions, task facets, recording/meeting metadata, and timestamped transcript segment mappings.
- A preview binds an actor and scope grant, expires after ten minutes, records every referenced revision and the snapshot digest, and verifies managed files. Apply checks those guards and hashes again, then creates new monotonically increasing revisions in a single canonical batch.
- Property names can evolve, but incompatible types, schema versions, configuration or removed option identities produce an explicit conflict. Raw historical values remain in the snapshot. No shared property definitions, view definitions, or other record values are rewound.
- Transcript restoration preserves stable block/segment/meeting IDs and offsets. Deleted blocks can be restored without foreign-key failures from retained memory evidence. Search sees restored content through normal projections.
- Memory entries, approvals, forgotten/disabled/superseded state, and their source evidence are not copied out of page snapshots. A restored source receives a new revision and cannot silently make old evidence current.
- Trash subtree preview selects each page's last retained live snapshot, validates reference ownership and parent dependencies, orders the reviewed operations by the historical hierarchy, and uses one atomic batch. A concurrent edit fails the entire reviewed set.

Historical snapshots from before schema-evidence capture cannot safely restore non-title property values or missing meeting metadata. The preview reports that limitation explicitly; readable bodies and raw retained history remain available. A single reviewed batch is bounded to 200 subtree pages and 1,000 revision guards. For larger subtrees, restore ancestor pages individually before recovering smaller descendant groups; unusually large individual snapshots remain retained/exportable.

## Complete native backups

`CreateBackup` writes a new destination selected by the native folder picker and never overwrites an existing folder. It takes a consistent SQLite `VACUUM INTO` snapshot while canonical writes are serialized and pins managed assets for the later copy. The entire native database preserves databases, links, views, history, import mappings/reports/raw source evidence, conversation data, job receipts, and memory states.

Version 2 manifests declare the database, every canonical managed asset, and every retained recording journal/source object with SHA-256 and size. Interrupted capture includes the complete raw source, including bytes durably written after the last journal checkpoint. Segment ranges and their hashes are checked as well as the full-source hash. Active capture is rejected with an actionable stop/recover message; startup marks orphan capture journals interrupted so crash data can be backed up before finalization. Completed recording journals remain provenance while playable audio is retained as a managed asset.

Verification rejects incomplete directories, malformed/unsafe/duplicate paths, symlinks, invalid lengths or hashes, missing assets, database/manifest disagreement, SQLite integrity failures, foreign-key violations, and invalid recording journals. Version 1 backups remain readable, with an explicit warning that they did not inventory recording drafts.

## Staged restore and external retention

The native adapter returns a one-use ten-minute review token, never a renderer-controlled path. Restore verifies that the selected backup still matches the review, copies the declared objects into a sibling staging directory, verifies the copies, runs normal schema initialization, revokes unused action approvals, consumes old restore handles, removes transient file-ingest capabilities, and rebuilds keyword search. No inference workers run during staging; semantic indexes are derived and regenerate when a suitable pack is available.

Publication reserves a fresh destination and keeps an `INCOMPLETE` sentinel until all staged data has arrived. The kernel refuses incomplete workspaces. The source backup and the open workspace remain unchanged. A restore receipt identifies the source manifest. The user can open the resulting folder as a separate installation.

Retention settings visibly state that retained page revisions, recovery points, trash and referenced assets are kept indefinitely. External backup keep count defaults to all. Choosing a finite target does not delete anything automatically: the native review lists older verified backups from the same workspace. Explicit cleanup revalidates the exact reviewed set and refuses backups with unknown files or changed manifests. Other workspaces, incomplete backups and unverified directories are retained.

- Atomic subtree conflicts and isolation from unrelated database records/shared schemas.
- Historical transcript restoration with correct timestamp navigation.
