# Phase 2A — Notion migration and portable export

Implemented in `internal/workspace/import*.go`, `internal/workspace/export.go`, `app_import_export.go`, and `frontend/src/imports/`.

## Workflow

The Import & export panel accepts a native file selection for ZIP, Markdown, or CSV. The user selects a stable source namespace, inspects a complete compatibility inventory, changes non-title CSV property types, resolves existing-source conflicts, and commits. Each commit is an atomic unit through `import.applyPlan`, with canonical page/block/database mutations, revision guards, history, file references, committed events, and search projection hooks. Pause occurs after a durable item boundary. Plans and the next cursor survive process restarts. `imports.enqueue` and the registered `IMPORT_NOTION` job handler also run the same units under job leases and approval-bound plan hashes, with progress and cancellation through the existing jobs service.

Every discovered archive member, parsed CSV row, and reconstructed directory has exactly one of the five outcomes: Preserved, Adapted, Partial, Unsupported but retained, Failed. Completion describes processing completion; reports with failed or partial items have a partial result. Known supplied omission statements and unknown source completeness are displayed separately. An ordinary Notion export is never assumed complete. CSV numbers remain decimal strings; formula, rollup, relation, and view semantics are never inferred from display values.

ZIP members are streamed into hash-addressed managed files rather than extracted to source-named filesystem paths. Absolute paths, traversal, drive paths, backslashes, symlinks/special files, duplicate/case-colliding names, excessive compression ratios, oversized members, and corrupt decode/CRC results are rejected and reported. The original container is retained as evidence for rejected members. Limits are 10,000 expanded files/rows, 64 MiB per member, 1 GiB expanded total and source archive, and 256 CSV columns. No archive member name selects a disk destination.

Markdown becomes canonical headings, paragraphs, quotes, bulleted items, code blocks, dividers, links, and managed images. Unhandled syntax remains readable as literal text, and exact original bytes are retained. Relative page links become Trove page links; local file links become managed file links. Unresolved relative links cause Partial outcomes. Missing directory nodes become pages; Notion filename IDs establish source identities. CSV records can attach to an unambiguous supplied record-body Markdown page. Invalid typed values become explicit readable fallback blocks with retained row evidence instead of being silently discarded.

Re-imports compare namespace + external identity (or explicit derived path identity), source hash, and recorded local page revision. Identical, unchanged source/local pairs remain untouched. Other existing matches require keep-local, page-body replacement, or separate-copy review. Live revision checks reject edits made after preview and during resumed processing. Keeping local data still retains incoming evidence. Database schema replacement is deliberately refused: users keep the local database or import a separate copy; schema migration requires separate review. Absence from a later export never implies source deletion.

Portable export writes a new ZIP containing Markdown, CSV, attachment bytes, and `trove-manifest.json`. The manifest contains hierarchy, exact canonical page/block data, typed cell values, view definitions, supplied provenance, asset hashes, and prior import evidence. Import verifies portable attachment hashes and uses supplied hierarchy. The readable format roundtrip retains body text, supported links, assets, and CSV data. Canonical metadata that cannot be reconstructed remains in the retained manifest. Native backup is the full-fidelity route for trash, history, retained schemas, approvals, and model-independent restore; portable export explicitly states these omissions.


Fixtures cover representative hierarchy, internal page links, assets, unsupported HTML, precise decimal CSV values, no formula inference, traversal/drive/case-collision rejection, interrupted import/reopen/resume, explicit keep-local conflict handling, edited inference with invalid-value fallback, portable ZIP roundtrip and manifest evidence, and a leased job attempting to commit a different unapproved plan. The canonical report is schema-validated.

Remaining qualification: real large Notion export distributions and the maximum archive sizes have not been benchmarked. Markdown tables, nested rich formatting and special Notion behaviors are retained readably/raw rather than claimed to retain their original interactive semantics. Portable manifests retain exact view and richer property definitions, but portable import does not automatically instantiate arbitrary view/formula definitions. The first shell transaction creates hierarchy placeholders before per-item commits; maximum-size responsiveness needs a measured large-export test. Preview emits throttled byte-reading and member-inventory progress plus parsing/ready stages to the desktop. The backend request remains synchronous; only commits use the durable job queue. Full preview bodies are materialized in memory within the documented size bounds. These limits are visible here rather than presented as completed performance qualification.
