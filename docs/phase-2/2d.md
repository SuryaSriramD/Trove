# Phase 2D: recording and meeting intelligence

## Delivered workflow

The Meetings surface starts explicit native microphone capture, uploads a local recording, lists interrupted captures, and opens canonical meeting pages. Existing meeting pages show the same transcript/audio detail. Microphone permission is requested only through the explicit Record microphone action. System audio and reliable speaker identification are outside this release.

Capture begins with a workspace-owned `recordings/<uuid>.f32le` descriptor and atomic JSON journal. The native helper flushes captured samples before each progress event. Each checkpoint hashes its contiguous durable byte range. Recovery includes bytes flushed after the last journal update and refuses altered acknowledged segments. On workspace reopen, orphaned capture journals become interrupted, so backup can preserve them before finalization. Stop/recover converts to mono PCM16 WAV, attaches the managed asset, creates the canonical meeting, and then removes duplicate raw capture bytes. The retained journal records capture segment hashes and resulting page/meeting/file identities. Finalization is idempotent.

Local uploads preserve source assets. Valid raw float32 uploads additionally receive a browser-playable WAV while retaining the original attachment. Unsupported encoded formats remain attached to the meeting and produce a recoverable decoding error; the service does not launch arbitrary codecs or infer content from a filename. Supported recognition inputs are 16 kHz mono PCM16 or float32 RIFF WAV and explicitly validated float32 PCM, bounded to two hours. Nonfinite/out-of-range floats, truncated or ambiguous WAV chunks, and invalid durations are rejected.

Transcription uses queued whisper.cpp work outside SQLite. The durable audio is divided into minute units. Each unit reserves stable segment/block IDs, validates relative timestamps, converts them to absolute offsets, and atomically commits paragraphs, canonical transcript segments, history/outbox, and the unit receipt. Restart/retry skips committed units. Retry resumes the original job and model pack; completed meetings reject duplicate recognition. Canonical meeting/file revisions remain fenced; the dedicated transcript commit rebases its append-only destination page guard atomically inside the same writer transaction. An edit between the worker's guard snapshot and commit cannot invalidate completed inference or overwrite the edit. Generic job commits retain strict source guards. Audio survives cancellation and errors. The UI shows progress, retry/resume, cancellation, timestamped text, and audio seeking. Transcript edits update canonical transcript text and evidence hashes. Search consumes the canonical page/block/timestamp locations.

Meeting notes require an installed instruction model. The summary worker processes all transcript text in bounded excerpts and requests each category separately. A constrained llama.cpp GBNF grammar fixes the output shape and restricts citation labels to the actual source segments in that excerpt; the service then validates canonical IDs, rejects duplicate JSON keys and trailing content, and checks source freshness. This applies to every summary, key point, decision, question, and proposed action item. It saves an evidence-linked review draft without mutating the meeting or creating tasks. Approval appends notes only if the evidence is still current. Proposed action items recheck the original draft evidence both before the review preview and at creation. Voice-note and action-item conversions display editable title/body previews, then create canonical pages or canonical task records through guarded mutation batches. No separate task state or competing memory record is created.

## Integration

- `MeetingPanel({ workspace, onRefresh, onNavigate, pageId? })` supplies either the complete Meetings surface or inline meeting detail. Audio elements use `data-meeting-id` for external search/citation seeking.
- Desktop methods: `StartMeetingRecording`, `StopMeetingRecording`, `SaveMeetingRecording`, `MeetingRecordings`, `PickMeetingAudio`.
- Desktop lifecycle calls `stopRecordings()` before switching/closing a workspace.
- Services: `meetings.source`, `meetings.drafts`, `meetings.transcribe`, `meetings.applyDraft`, `meetings.createFromTranscript`.
- `SUMMARIZE_MEETING` and `TRANSCRIBE_AUDIO` are installed worker handlers. Existing registered search/import/backup handlers are retained.
- Recovery/backup must retain interrupted `recordings/` artifacts and validate file hashes; the JSON capture journals remain provenance after canonical WAV publication. Meeting/transcript snapshot restoration is integrated by Phase 2E.

## Verification and remaining qualification

New deterministic tests cover crash-tail recovery, checkpoint tampering, idempotent finalization, rejection of autonomous capture, missing/stale summary evidence, transcript text synchronization, reviewed canonical task creation, transcription resume after reopening with no repeated minute, absolute timestamps, malformed float rejection, PCM conversion, and preservation of long Unicode prompt text.

`TestOneHourSourceDoesNotBlockEditingDuringRecognition` uses a one-hour-sized source and a controlled blocking recognizer. A guarded same-page edit completes while recognition is blocked. This proves the writer is not held by inference; it is not a real one-hour Whisper throughput/accuracy or microphone hardware qualification.

The real bundled Whisper integration test passed on the JFK WAV with the installed verified speech pack: queued recognition, canonical transcript commit, and reopened page content were checked.

`TestRealOneHourTranscriptionKeepsEditorResponsive` additionally processed the public JFK speech sample repeated to exactly 3,600 seconds through the real bundled whisper.cpp worker, queued job runtime, and all 60 durable minute commits. On the tested Apple Silicon host it completed in **99.73 seconds** under the aggregate race-enabled run, produced **694 transcript segments**, and allowed **47 same-page guarded edits**, with a maximum observed edit latency of **235.89 ms**. See [native one-hour evidence](../../evidence/phase2/one-hour-native.json). This is a real native processing and service-responsiveness qualification using repeated speech; it does not measure diverse real-meeting accuracy or microphone hardware behavior.

`TestRealLocalMeetingSummaryRequiresReview` passed with verified Qwen2.5-1.5B-Instruct Q5 pack `01990000-0000-7000-8000-000000000105` and grammar-constrained generation. The fixture preserved the actual beta-on-Monday decision, Maya's checklist commitment, and the specific offline-activation question, with canonical source citations. It then applied the notes only through explicit user approval. See [native meeting-note evidence](../../evidence/phase2/meeting-native.json). The Meetings UI prefers installed pack 105. Compact pack 104 remains selectable but did not meet this structured quality fixture before constrained decoding; it is not the qualified default for meeting intelligence.

The targeted recovery/transcription/evidence tests also passed under Go's race detector. A deterministic regression places a user edit exactly between the transcript guard read and commit; it verifies retained user content, correct effective audit revisions, and idempotent replay. Separate regressions confirm meeting/file changes, page deletion, and changed destinations still reject the commit. Native grammar metadata is bounded to 64 KiB and accepted only for generation. TypeScript checks passed.

Run the opt-in native checks with the verified local bundle/model cache and system memory/Metal access:

```sh
TROVE_NATIVE_INTEGRATION=1 go test -tags sqlite_fts5 ./internal/workers -run 'TestRealDurableTranscriptionJob|TestRealLocalMeetingSummaryRequiresReview' -count=1
TROVE_LONG_AUDIO_INTEGRATION=1 go test -tags sqlite_fts5 ./internal/workers -run TestRealOneHourTranscriptionKeepsEditorResponsive -count=1
```

Microphone permission/capture on real hardware, interrupted real long microphone recordings, and accuracy across natural meeting audio still require device qualification. Model output quality is distinct from evidence identity validation: valid segment references do not mechanically prove an inferred statement, so generated notes remain reviewable proposals.
