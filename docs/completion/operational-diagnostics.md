# Bounded operational diagnostics

The kernel retains a local ring of operational events for application initialization, service requests, imports, search, model preparation/completion and job transitions. Events contain only fixed component/operation/outcome/error-code labels, UTC timestamps, bounded elapsed milliseconds and bounded numeric counts. Unknown labels become `other`. Request payloads, exception messages, paths, credentials, user content and workspace/page/job identifiers are not accepted fields.

At most 512 events and seven days of history are retained. Every event is age-filtered, including unordered historical events. Persistence is a disposable JSON snapshot capped at 256 KiB, coalesced in a background writer. Recording never waits for filesystem I/O. Shutdown waits at most two seconds; a stalled writer may finish later while holding its separate diagnostic ownership lock. This is not a crash-durable audit log or part of canonical workspace history.

Directory creation and file access start from a pinned workspace root. Both `logs` and `operational` reject symlinks and non-private storage before effects in that component. Pinned directory/file handles are checked for owner privacy; the lock must be a regular, singly linked file. Existing invalid, oversized, linked or unsafe history stays untouched and persistence reports its unavailable/invalid state. In-memory sanitized events remain usable. No permission repair or external-folder traversal is performed.

Settings adds an **Include operational diagnostics (no content or raw errors)** checkbox, off by default. When selected, `diagnostics.json` appears in the exact support preview and manifest before the native save dialog. Later events cannot alter approved bytes. Changing selection invalidates the preview. Default support exports retain their original two-file metadata-only shape. Page titles and text still require their separate explicit content selections.

`initialize` and `post_migration_initialize` durations measure service initialization after the database pools open. They do not measure total launch or migration duration. `worker_finish` describes handler completion; only a successful canonical transaction emits a job `transition` state. An invalid or expired lease cannot produce a successful committed job event. Model preparation records the bounded context-token count without recording prompt text. Request diagnostics aggregate methods into fixed categories and sanitize errors, including batched command responses.

The evidence manifest retains the original test-configuration failures alongside corrected results. Privacy tests inspect exported ZIP bytes, late-event preview immutability, hostile labels, linked ancestors, retention and invalid job leases. The broad workspace race run preceded the final review fixes; the final affected regressions cover the revised implementation. Browser checks exercise consent and invalidation in the actual Settings component. This package does not qualify a packaged native candidate or Windows/Linux execution.

The existing startup trace and separate model/performance evidence remain authoritative for those measurements.
