# Search preserves words across rich-text formatting

Native testing of candidate `be6fc81` saved `important` across two formatting runs (`imp` and `ortant`). The editor displayed and retained the correct word, while the search projection inserted a space and the quick switcher could not find `important phrase`. The original failure remains in [candidate evidence](development-candidate-be6fc81.md).

Declared rich-text fields, captions and database text values now concatenate their runs exactly, retaining Unicode and existing whitespace. Independent cells, tabs and other lists retain structural separators. Presentation metadata and link targets do not become source text. The same readable projection feeds search, AI evidence, proposal previews and personal-review record fields. Independent review caught the latter direct consumer; its separate failing regression is retained.

A versioned derived projection marker queues every existing page for one bounded rebuild when an older workspace opens. Search drains that durable queue before retrieval, replacing chunks, clearing obsolete embeddings through the existing sqlite-vec deletion triggers, and advancing the index generation. Canonical values, formatting, identities, revisions and history are unchanged. Current-version initialization does not repeatedly invalidate the index. Older/restored workspaces may pay a first-query rebuild cost; no canonical schema migration is required.

All five new regressions fail against the old implementation: marked-word search/citations, Unicode and cell boundaries, database text, reopening an old persisted projection exactly once, and removal of stale sqlite-vec coordinates. After repair, **92 affected race tests/subtests pass**. [Source hashes, commands and raw before/after results](../../evidence/completion/richtext-search/manifest.json) preserve the comparison. Packaged interface rechecking is a separate pending step and no release gate is closed by these service tests.
