# Phase 1 integration contract

Each package has a dedicated implementation agent. Available concurrency is three package agents plus the coordinator; the remaining package agents start as slots free. Package ownership prevents concurrent edits to the same implementation files. All five acceptance gates remain required, including integration in a packaged application.

| Package | Owner | Implementation ownership | Acceptance evidence |
| --- | --- | --- | --- |
| 1A | phase1a_kernel | internal/workspace core, pages, mutations, permissions, jobs, events; root Go dependencies | Real SQLite restart, atomicity, conflicts, policy, job recovery tests |
| 1B | phase1b_desktop | frontend except frontend/src/database | Browser/editor structure, clipboard, international text, focus/accessibility, save/reopen tests |
| 1C | phase1c_databases | internal/workspace/database.go, tasks.go and tests; frontend/src/database | Shared four-view record queries/mutations, task projections, typed properties, restart |
| 1D | phase1d_recovery | internal/workspace/files.go, history.go, backup.go and tests | Content-addressed assets, scoped reads, revisions/trash restore, consistent backup/retention |
| 1E | phase1e_native | internal/native, native helpers, packaging support and runtime tests | Actual model packs/helpers, bounded transport, cancellation/recovery and packaged worker launch |
| Integration | coordinator | app.go/main.go, Wails configuration, root packaging integration, contract extensions, aggregate evidence | Packaged create page/record + file, terminate/restart and verify content |

The backend's trusted `internal/workspace.Kernel` opens/creates a workspace, holds its process lock and exposes Dispatch with a server-created OwnerContext. The Wails facade does not accept actor or raw database/path authority from the renderer. Content writes use canonical BatchRequest. Native file pickers return opaque selection handles; PrepareFile stages bytes, and AttachFile commits the relationship through services.

The frontend calls `window.go.main.App.Dispatch(method, jsonRequest)` and parses the response envelope. Method names are `workspace.snapshot`, `batch`, `allocateIds`, `readPage`, plus declared service operations. Workspace snapshot returns domain entity arrays and workspaceId/scopeGrantId/snapshotCursor. `PickFile()` resolves a native selection into an opaque handle. Files render through scoped `/files/<fileId>` asset URLs. `workspace:changed` and `jobs:progress` events invalidate caches; canonical writes remain durable if notifications are missed.

1C/1D extend the same workspace package through registered command/query handlers, not an independent DB handle or commit path. They share the kernel's Mutation transaction, guards, entity revision touches, page capture and policy checks. A record and its page remain one revision aggregate. Native workers have only approved inputs and never receive the workspace database.

Contract 1.1 adds optional page icon/cover/archive metadata and accepts icon/cover changes in page.update. The old workspace SQL remains migration 0001; the kernel applies an additive metadata migration. Existing Phase0 fixtures remain valid. Strict older readers require the matching contract upgrade and must preserve unknown metadata on native export.

Native binaries install under `Trove.app/Contents/Resources/native`. Chat, embedding and speech packs remain separate verified manifests. The development package can be ad-hoc signed on this host; no valid Developer ID identity is currently installed. Distribution notarization and a truly independent clean-machine run must be reported as their actual status rather than inferred from a development-machine launch.
