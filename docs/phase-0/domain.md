# Canonical workspace contract v1

This document resolves PRD §§15–16, 21 and TRD §§5–8, 23–24, 31 against the executable definitions in `contracts/domain.schema.json`. `contracts/examples/domain-workspace.json` is the complete reference graph. `schemas/workspace.sql` is migration 0001 and proves the foundational relational constraints; it is not a running workspace service. JSON uses camelCase and SQL uses snake_case. Adapters must use the service contract; they never own a second write path.

## Identity and ownership

All local entity IDs are lowercase UUIDv7 strings generated by the kernel. IDs are permanent across rename, reorder, move, trash/restore and repeated imports. They are globally unique across entity kinds. An external ID, filename, page path or content hash is never a local entity ID. Integer revisions are transported as canonical decimal strings in the range 1–9223372036854775807; there are no leading zeros, floating-point revisions or JavaScript `number` conversions. Revisions are monotonic, never reused, and compared for equality during writes. Exhaustion returns an explicit error rather than wrapping.

| Entity | Canonical ownership and reference contract |
| --- | --- |
| Workspace | Owns one canonical database and managed immutable assets. No tenants or collaboration accounts. |
| Page | Owns a title, metadata, revision and ordered block tree. A page with zero blocks has a valid empty body. A parent page affects navigation; it does not implicitly grant AI scope. |
| Block | Owns its UUIDv7 ID, page ID, optional parent block ID, sibling sort key, per-type schema version and typed payload. A block parent belongs to the same page. |
| Collection | Owns schema/property definitions and its canonical records; `collectionId` is TRD `Database.id`. Its owning page and title property are explicit. Exactly one primary title property projects `Page.title`. |
| Record | Belongs to exactly one collection and has a non-null, globally unique `pageId`. Every database row is a record with a page body; this requirement does not mean infrastructure rows such as jobs or option tables need pages. Record title is its page title. |
| View | Owns query/layout configuration and references exactly one collection. There are no view-owned records or copied row values. Moving, renaming, deleting or unlinking a view does not change record identity. |
| Container | Presents collections without owning their records. A database container may reference several distinct collections. A project container additionally defines explicit memory scope. Container membership never merges source collections. |
| File | Identifies immutable content by a workspace-unique SHA-256 and one local UUIDv7. A new byte sequence creates a new file identity; repeated bytes reuse the file. Attachment labels may differ without duplicating bytes. Storage keys are derived `files/<first two hash chars>/<hash>`, never user paths. |
| Meeting | Owns a page body and references a managed recording file. Stable transcript segment IDs and block IDs anchor its transcript. Recording state does not become task state. |
| Memory | Owns a normal page body and an approved, scoped projection with source locators. It may refer to pages but cannot supersede live task/database values. |
| Task | Is a facet of a canonical record, not another record or independent content object. See `decisions.md`. |

`pageId` and `recordId` are distinct UUIDs. A record page is not shared by two records. The record revision equals its page revision: a page-body, title, record-property or task-status change advances the aggregate page/record revision once in the same commit. Collection/schema revisions and view/config revisions advance independently. Blocks have local revisions as well; page revision always advances when a block is added, edited, reordered, moved out or deleted. A cross-page move retains a block ID and advances both pages. Root block order is canonical, not an editor-only ordering.

Sibling `sortKey` is a 12-digit decimal ordinal string. Allocation uses available gaps; exhausting a gap rebalances that sibling list atomically and advances the page revision. Imported source ordering is mapped deterministically. Column/tab payloads reference stable child block IDs; they must agree with the block tree and cannot clone child content. Synced-block payloads reference a canonical content-source page by `contentSourceId`; instances never own copies. P1 can expose these relationships without changing P0 IDs.

Page/block parentage and project ancestry are acyclic. Same-workspace ownership, tree integrity, schema consistency and referenced property types are service validation obligations. SQLite enforces record bodies, title uniqueness, selected cross-entity foreign keys, task status linkage, file hash deduplication and sibling order. `reference_domain.validate_snapshot` adds graph constraints that SQLite's polymorphic JSON fields cannot express. Neither JSON Schema alone nor SQL alone replaces the entire validator.

## Reference and deletion semantics

Unlink removes a container/collection or navigation reference. Move changes parent/location and keeps IDs. Trash marks the selected canonical objects deleted, retains IDs/history/raw material, and creates a recoverable tombstone. Removing a todo occurrence removes that block only; trashing a task record trashes its page and makes every occurrence a readable unavailable-task reference. No cascade deletes canonical records because a view/container disappears. Hard deletion is a separate retention operation with explicit reference validation; a file remains retained while referenced by live content, history, import baselines or retained backups.

Record restoration restores its selected page, blocks and own values as a new revision. It does not rewind the shared collection schema or linked records. A value no longer accepted by the current property schema is retained in a mapping preview. Derived indexes, embeddings and thumbnails are disposable and never become authoritative content.

## Citations required at P0

`Location` contains `pageId`, `sourceRevision`, optional `blockId`, and optional transcript `{meetingId, segmentId, startMs, endMs}`. Transcript locations require `blockId`. `sourceRevision` is the aggregate page revision at retrieval, including the transcript/record content being cited. Timestamps are JavaScript-safe nonnegative integer milliseconds in half-open intervals `[startMs,endMs)` relative to the canonical recording, with `startMs <= endMs` and the range contained in the named segment. No text offset, title, URL slug or ordinal substitutes for stable IDs.

Resolving a citation checks the page exists and is live, then validates its revision, block ownership and transcript bounds. Changed sources return a stale-location result with the current revision; missing/deleted sources return an unavailable result. The caller can show retained source text/history, but cannot silently relabel it as current. A moved block can be resolved by its ID to the new page and reported as relocated; the old locator is not rewritten in the historical answer. P0 opens the page and can highlight/seek the cited location. The full user-facing copy-block-link/navigation interface is P1 and does not postpone locator storage.

A retrieval chunk ID is index-specific and rebuildable. It must always carry the underlying `Location`; it must never be the sole durable citation. Memories use the same locator. All source text, including imported HTML and quoted instructions, is untrusted data.

## Provenance and import identity

Import mappings are unique on `(workspaceId, sourceSystem, sourceNamespace, externalKind, identity.kind, identity.value)`. `sourceNamespace` identifies the source workspace/dataset, not a transient import run. Kinds namespace page, block, property, source collection, view and container IDs independently. A derived locator is labeled as derived, with confidence; never fabricate an upstream ID. Ambiguous candidates block automatic remapping. Observations append import-run/source revisions; the retained common baseline supports three-way merging.

Source creators, editors, groups and timestamps are retained independently from the local mutation actor and local timestamps. Unknown identity details remain unknown. Imported people are historical/contact references, not invited accounts. Place values preserve label/address/coordinates/raw metadata without geocoding. Unsupported comments or structures retain raw source and readable fallback with explicit anchors or unresolved-anchor diagnostics.

## Conformance boundary

Run `python -m unittest discover -s tests -p test_domain.py -v` in the documented verification environment. These checks prove contract shape, representative graph semantics, the three-way-merge decision table, memory eligibility and SQLite constraints. They do not claim editor UX, importer fidelity on customer exports, native SQL driver behavior, packaged-app tests or inference quality. Those remain work-package acceptance gates in the requirements ledger.
